# v2.5.0 Release Notes

发布日期：2026-08-03
对应发布线：`v2.5.0` annotated tag（自 v2.4.0 起不再建 `release/*` 分支）

`v2.5.0` 没有新的患者功能面。这一版做的是把「测试全绿」和「能上线」之间的距离量出来，然后把它填掉——一轮 88 条部署就绪审计，加上对修复本身的一轮对抗复审（50 条），再加上第一次真正构建并运行镜像所发现的东西。

## 版本亮点

### 1. 生产 fail-fast 终于覆盖了它声称覆盖的东西

`validateProductionEnv` 此前有多处形同虚设。本次补上：缺 AI key、`postgres:postgres` 凭据（旧检查只认 `localhost` 字面量，在 compose 路径上是永久 no-op）、弱密钥、明文对象存储、生产用本地磁盘存储、`OCR_PROVIDER=baidu` 缺凭据、AI 接入点出境未确认。`env.test.ts` 从 15 个测试扩到 37 个——每道闸门一对「占位值被拒 / 真值通过」。

最要紧的一条不在代码里：**`NODE_ENV` 此前没有任何文档要求设成 `production`**，而它一旦不是，上面整块校验直接返回空错误列表。runbook 的必填表现在第一行就是它。

### 2. 同意机制从「有形状」变成「有效力」

PIPL Art. 29 的敏感个人信息单独同意、Art. 31 的儿童个人信息处理规则与监护人同意，现在都是**服务端强制**：`requireSensitiveDataConsent` 挡在 12 条写入路由前，`requireGuardianConsentForMinor` 用**服务端时钟**重算年龄（设备时钟可改，而这条保护的正好是儿童）。

四条写入路由**故意不挡**：`/me/consent`、`/me/sharing-preferences`、`/me/deletion-request` 及其取消。挡它们是循环——撤回同意之后就再也改不回来、也删不掉账号了。读取路径全程不挡：查阅和复制是政策赋予的权利，不是同意的奖励。

同意可以**撤回**了（迁移 020）。此前三份同意书都白纸黑字写着「可随时在隐私设置中撤回」，而账本是只增不改的。撤回是打标记不是删行——「撤回不影响撤回前已进行的处理」这句话只有行还在才证明得了。

隐私政策从五句占位文本重写成一份实质草案：处理者、联系方式、个人信息清单、每一项的目的、保留期限、接收方（点名 SiliconFlow 及其接入地址）。**尚未经律师审阅**，`legal-content.ts` 顶部写明了还缺什么。

顺带修掉了「隐私设置」底部对患者的三条虚假陈述：「区块链存证数据操作日志」（没有区块链）、「严格遵守 HIPAA、GDPR」（美国医疗法规，不适用）。

### 3. 容器栈变成它文档里描述的那套

`DATABASE_URL` 改成插值（此前 operator 填的托管库连接串被硬编码值静默丢弃，PHI 会写进一个没备份的卷，而 `pg_dump` 备份的是他们以为在用的那个库）；`POSTGRES_PASSWORD` 强制必填；`minio` 加入 `prod` profile（此前它在文档要求的命令下根本不启动，而上传路径没有回退，整栈全绿然后每次上传 500）；每服务 `mem_limit` 与日志上限；api 有 `stop_grace_period`；kb-service 不再拿到整份 `.env`。

优雅停机在容器里真正生效：Dockerfile 的 `CMD` 补上 `exec`，两个停机时间参数改为**有序而非叠加**并在构造时校验，第二次信号从被吞掉改为升级处理。

### 4. 数据安全

回滚真的能用了：手工跑 `_down.sql` 此前会留下 `schema_migrations` 幽灵行，让之后的前滚静默 no-op——而 runbook 写的正是那个坏序列。现在 `--down` 在一个事务里同时应用 down 文件和删除账本行。

备份从无到有：`db-backup.sh` / `db-restore.sh`，带行数与体积双重预检、`.dump.meta` 清单对比、绝对路径强制、凭据走环境变量而非 argv。

审计脱敏在写入边界统一，账号注销的抹除补齐了此前遗留在 `audit_logs` 里的手机号、邮箱和 IP。

### 5. 仓库第一次有了 CI

三个 job，覆盖 API（733）、移动端（298）、report-manager（181）。Python 那块是 [#106](https://github.com/OpenRareDisease/openrd/pull/106) 留下的缺口，也是最不该留的一块——`apps/report-manager` 把扫描件变成 API 提示词信任的结构化字段，它出错的形态是一条**静默错误的病历**。

CI 这件事的起点是 @FenjuFu 的 [#106](https://github.com/OpenRareDisease/openrd/pull/106)：仓库有 448 个测试而没有任何东西自动跑它们。

## 验证情况

### 已执行

- API 733 / 移动端 298 / Python 181，lint 与 typecheck 全绿；CI 在 PR 上实跑通过
- **镜像构建成功**，镜像内 tesseract 5.3.0（含 `chi_sim`）、poppler、Python 3.11、解析器路径可解析
- **升级路径**：迁移 013→020 应用到一个两个月前的有数据卷上，api healthy
- **同意闸门**：零同意行时 4 条写入全部 403 并带 `sensitive_consent_required`；记录同意后同一写入放行；读取路径全程 200
- **撤回**：对着真实表跑通闸门盲→同意→可见→撤回→再次盲，证据行保留
- **优雅停机**：容器内 SIGTERM → drain 5.008s → 关监听 → 关池 → exit 0
- **安全头**与**发布产物**：真实响应带 `X-Frame-Options: DENY` / `frame-ancestors 'none'`；bundle 内 `localhost:4000` 与 `chux-path-change` 均为 0 处

### 未验证 / 已知缺口

- **完整六服务栈在内存压力下的表现**。compose 上限合计 8.75 GiB，本机 Docker VM 分配 8.32 GiB，服务是分组起的。生产文档写的是最低 8 GB，理由是上限并非预留——合理，但未在峰值下验证。
- **国内首次冷启动拉模型**。warmup 日志显示 `hf-mirror.com` 把元数据请求 308 重定向回 `huggingface.co`；本机两者都通，GFW 后是否完成无法从这台机器验证。
- **隐私政策未经律师审阅**。这是发版硬门槛，代码审查清不掉。
- **KB 语料没有任何从仓库到全新主机的路径**。唯一权威副本在开发机上（9594 行 / 206 个 source_file / 164 MB）。部署前必须先 dump。
- **腾讯短信凭据与签名/模板审批**。模板必须恰好两个变量，否则启动全绿而每次发码在事务里静默回滚——看起来像「没人在注册」。
- **备份没有调度，恢复从未演练**；**没有任何告警**。
- 一次 API 测试失败在 30 次重跑中未能复现，也未定位。

## 升级前必读

从 v2.4.0 升级的机器，**在动 `.env` 之前**先读 runbook §1.0-a 与 §1.0-b：

1. **密码死锁**——`POSTGRES_PASSWORD` 只在卷初始化时生效。线上卷存的是 v2.4.0 硬编码的 `postgres`；填新密码认证失败，填 `postgres` 被 `validateProductionEnv` 拒。必须在旧栈还跑着、旧密码还有效时 `ALTER USER`。
2. **collation 漂移**——镜像底层 glibc 变化后，26 个文本列 B-tree 索引（含 `app_users.phone_number`、`patient_documents.checksum` 的唯一索引）不再可信。`REINDEX` 再 `REFRESH COLLATION VERSION`，顺序不能反。

两条都是把 v2.5.0 的栈起在一个两个月前的真实卷上才发现的。

## 一句实话

这一版发现的缺陷里，有相当一部分是**注释断言了代码没做的事**——同一条发布线上出现了五次。它们几乎都不是测试抓到的，因为测试测的是函数本身，不是有没有人调用它。抓到它们的是被指示去推翻结论的对抗审查，以及第一次真正把镜像构建出来运行。
