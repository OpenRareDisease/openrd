# v2.6.0 Release Notes

发布日期：2026-08-13
对应发布线：`v2.6.0` annotated tag

两块新功能，加上第二块在法律上必然带出来的第三件事。

## 版本亮点

### 1. 问答终于看得见今年新开的试验

在这一版之前，问「有没有在招的临床试验」，回答来自建库时导入的语料——那些文档对
机制的描述是对的，对招募状态的描述必然是错的，因为招募每周都在变，而一份静态文档
做不到。对一个尚无获批疗法的病来说，「附近有没有在招的」恰恰是那个问题，而我们过去
给的是一个带日期戳的猜测。

现在 `trial_records` 里有 92 条真实的 FSHD 研究，来自 ClinicalTrials.gov v2（公开
接口，无需 key），由宿主机定时任务刷新，**永远不在请求路径上**——上游变慢不会变成
回答变慢。主键 `(source, source_id)`，重复抓取是更新而不是堆积。

每条记录带的是注册库自己的登记号、标题、状态和最后更新日期，加上申办方、期别、试验地点这些注册库填了才有的项——填了就显示，没填就不显示，本平台不替它补。

- **入组标准和试验结果没有抓。** `CTGOV_FIELDS` 是钉死的字段清单，
  `eligibilityModule` 和 `resultsSection` 不在上面，所以这两样连 `trial_records.raw`
  里都没有——不是抓下来不显示，是从未请求过。名单之前就写着「本页不判断你是否符合
  入组条件，也不介绍试验结果」。同样被这张清单挡在外面的还有
  `contactsLocationsModule` 里的研究者姓名与电话邮箱：只要了 `locations.country`。
- **注册库的原文里，只有枚举词会被译成中文，而且出自手写的固定表。** 取值范围由注册库
  自己规定的那些词走手写映射，映射里没有的按注册库的原词显示；试验自身的文字，标题、
  申办方、地点，一律按原文逐字呈现，不翻译。建库语料里 `Recruiting` 被机器译成了
  「招聘」，而且因为没留下英文，没人能发现——这条规则就是从那儿来的。
- **不声称这份名单是全的。** 抓取日期显示在名单上方；这个日期读不出来时，页面不显示
  名单，而不是显示一份没有日期的。ClinicalTrials.gov 那半边最近一次刷新没成功或没
  返回时，页面用一条横幅说明手上这份是哪天抓的。

**国内注册库（chinadrugtrials.org.cn）接了，返回的是 0 条 FSHD 试验。** 这是注册库
自己的答案，不是抓取失败——它对首次请求返回 202 反爬，随后 200 加「共 0 条记录」。
这两种情况在数据里是分开的，因为「我们没找到」和「我们没能查」对患者不是同一句话。

### 2. 一个说不了谎的管理后台

给管理员用：患者名单、单个患者的档案与导出、全量 CSV 导出，加上几个只读的运维视图。
改患者档案只有一条路——`PUT /patients/:userId/baseline`。整个设计问题就一句话：**管理员填的
东西，绝不能被读成患者自己说的。**

这个区分是承重的。患者递给神经科医生的临床护照上，「基因确诊」和「未经基因确诊」是分开
印的，因为医生读到这两个的反应不一样。一个代填进去、印出来却像是患者本人陈述的值，会让
这份护照对**所有**患者都不再可信，不只是被改过的那个。（护照上没有「自述」这个词；
诊断那几行的值也不会因为「没有代填记录」就署到患者名下——那几行的来源里根本没有
「本人填写」这一档。）

所以来源是按字段存的（baseline 上的 `fieldProvenance`），而且**只有我们自己人写
入才会留下记录**——不需要回填，也不会把任何既有记录追认成别人填的。

这里有一条界限，这一版反复踩到过：**「没有记录」证明的是「我们这边没写过」，不是
「患者自己打的字」。** 一个值可以完全不经过这个块就进到基线字段——从上传的报告
OCR 出来、读取时被 autofill 填进空列。所以给医生看的页面上，任何一处都不会因为
「没标记」就署上患者的名字；它只说这一项没有代填记录。

**可写的是身份与病史，不是测量**：姓名、称呼、所在地区、出生年份、确诊年份、家族史、
起病部位、备注。白名单制，写别的返回 400 并点名被拒的是哪几个字段。导出层把来源一路
带到每一种格式。

**FSHD 分型、D4Z4 重复数、单倍型、甲基化不在这张单子上。** 它们是化验结果。照着电话
里念的报告打进后台，落下的是一个长得像化验数据、却不是任何人测出来的数字，而下游读
它的每一处——一条临床建议、一份登记库导出——都没有办法从值本身看出这一点。所以后台
没有给它们画输入框，服务端也拒：改动其中任何一项都返回 400 并点名，**连清空也算改动，
一样被拒**。

**这限制的是谁能打字，不是这几项的值从哪来。** 它们从患者上传的基因报告里读出来；
分型和 D4Z4 另外还在患者的「编辑资料」里有框，单倍型和甲基化在任何表单上都没有。

护照诊断那一块里，每个值都带着自己的来源，说的是这个值**从哪来**，不是该去哪儿改。
（印法随载体不同：分享给医生的那一页印成值后面的括号，患者手机上的护照和导出的
PDF 印成值下面单独一行。）能出现的只有这几种：**（报告读取）** 值是本平台从这份档案的
基因证据那一份上传件里读出来的——不一定是他传的最后一份，也不保证那一份是化验所出的
报告，基因这几项只从那一份读；**（管理员代填）** 是本平台的人写的，什么时候写的记在
「字段来源」里；**（非本人填写，来源不明）** 是档案里有一条代填记录、而那条记录本身
读不出来，只能确定这个值不是患者填的；**（来源无法确定）** 是值在档案里、而本平台说不
清它当初怎么进去的，这时候本平台不替患者认领这个值。值是空的那几格什么来源都不印——
「—（未填）」是同一件事说两遍。

**没有一种叫「本人填写」。** 一个值可以完全不留痕迹地进到档案里（读取时被 autofill 从
报告里补进空栏），所以「没有别的来源记录」推不出「他打过字」，这几行里就没有这一档。

**这一版把「打开那份报告去改」从来源旁边拿掉了，是有意的收窄。** 这句话成不成立，取决
于那份报告此刻的状态——识别还没跑完、识别失败、还没开始识别的报告，详情页上根本不画
修正入口，服务端也会拒。而护照、分享页、PDF 这一家都不读报告状态，它们只知道值和它的
来源。所以这些页面只说值和来源，把「改」留给报告详情页本身——那一页知道状态，也只有它
知道。**留下来的只有指向「编辑资料」的那一句**，因为那是一个不问报告状态的框：分型、
D4Z4 重复数和确诊年份都在那张表单上。代价是想改单倍型或甲基化的患者多点一下；换来的
是不再对着一部分人说不成立的话。

**报告详情页也不是什么都能改。** 它收的是报告名称、报告时间，以及分型 / D4Z4 重复数 /
单倍型 / 甲基化这几项基因结果，服务端的可修正字段白名单也是同一组。**诊断日期不在里
面**——要改是在「我的 → 编辑资料」里填「确诊年份」，填了保存，护照上的日期就变成那一年
的 1 月 1 日。护照上印的日期**未必就是那个框里的东西**：日期也能从别处进到档案里而年份
栏空着，所以那一句只说框能做什么，不说框里现在是什么。客服手册
（`docs/runbooks/v2.6.0-deploy.md` §3.4）按这个分岔写，念错方向的那一半会让患者在报告
页上找一个不存在的栏位。

角色拿不到自己头上：注册的枚举里没有 `admin`，角色是**每个请求现查数据库**的（所以
撤销在下一次调用就生效，不用等 token 过期），而且**读也审计**——在这种后台里，看了
一次病历才是要紧的事件，不只是改了一次。审计行写在 handler **之前**，审计写失败
返回 503：记不下来的读取就不发生。403 不审计，因为被挡住的非管理员不构成一次访问。

**这条只对撤销的方向成立。** 授予不会自己传到一台已经登录着的设备上：服务端立刻就
认新角色，但 App 画不画后台入口读的是登录那一次存在设备上的角色副本，没有任何地方去
刷新它。被授予的人要退出重新登录一次才看得见入口——部署手册的上线顺序在授予那一步
写了这件事。

### 3. 政策第 9 条承诺过要再问一次

隐私政策写着：接收方或目的发生实质变化时，会在应用内重新征求同意。给病历加一个
管理员可读写的后台，正是这种变化。

所以这一版每个账号下次打开都会先看到一屏——是一屏，不是弹窗，因为变化是「另一个人
现在可以读你的病历」，这件事配不上一个可以随手划掉的条。它先用人话说变了什么，版本号
放在下面，因为版本号不是患者用来做决定的东西。

**「暂不同意」和「同意」一样大**，选了就本次不再问，并把政策已经给的权利（导出、注销）
指出来、带过去。

**它没有说拒绝就能阻止管理员读你的档案，因为它不能**——API 里没有任何地方把管理员
访问和这个台账挂钩。有一条测试专门钉着这句话不许出现。拒绝**应该**改变什么，是要和
律师定的问题，这一版把它记下来，而不是糊过去。

## 修复

- **转诊资料在管理员录入确诊年份时印错了。** 那份患者要亲手交给神经科医生的文档，会先印
  「本平台尚无任何诊断依据记录 —— 以下内容仅为患者自述与自测」，四行之后又印出那条
  记录里的诊断日期。四态枚举改成了带穷尽守卫的 `switch`，第五个状态会编译不过，而不是
  悄悄落进「无记录」那句。
- **患者清空基线里那几个同时存进独立列的字段，旧值不会跟着消失。** `upsertBaseline` 用
  COALESCE，于是「显式传 null」和「没传」无法区分。改成按是否传入判断。
- **Art. 29 的单独同意被并进了入口的重新同意屏。** 对从未给过这项同意的账号，它会在
  开屏时连同政策更新一起问——而「单独」这两个字恰恰禁止这么做。它回到了首次上传时
  自己的场景里。
- **「我的」页脚同时说错了三件事**：产品名写成了仓库名、版本号停在比实际早一年半的
  1.0.0、年份写着 2024。三个现在都不是手打进这个页脚的了。
- **`scripts/admin-role.mjs` 进了运行时镜像。** 第一个管理员必须在跑着的生产栈上产生，
  而不装它的话，手册就只能叫运维在 psql 里手写 `UPDATE app_users`——那会丢掉脚本在
  同一事务里写的 `audit_logs` 行。在一个「连读都审计」的后台里，唯独创造读者的那个
  动作没有记录，说不过去。

## 运维必读

部署步骤见 [`docs/runbooks/v2.6.0-deploy.md`](../runbooks/v2.6.0-deploy.md)。**它是
v2.5.0 那份的增量，不是替代**，先过一遍那份再看它。四件容易漏的：

1. **数据库这次要从 020 跑到 027，其中 021–024 的 `_down` 是 `DROP TABLE`**——分享
   链接、量表作答、跌倒记录、取件码，都是患者自己录进去的；022 的回滚还会把
   `independentlyAmbulatory` 折回布尔，`'unable'` 和 `'assisted'` 从此分不开。025
   重建 cohort 索引时对 `patient_measurements` 持 `ACCESS EXCLUSIVE`，**读也挡**。
   迁移随 api 容器启动自动跑，所以 pre-flight 要在拉栈之前做。见手册 §1.1。
2. **反代必须放行 `/s/*`。** 护照分享页挂在 `/api` 之外，只配了 `handle /api/*` 的
   配置会把链接交给前端静态站，医生拿到的是一张 HTTP 200 的「页面未找到」，而
   `opened_count` 一直是 0。（「这个链接打不开了」是 API 自己那张 404 失效页，看到
   它说明反代是对的。）改完 Caddyfile 还要重建 caddy 容器，`up -d` 不会重建它。
3. **试验刷新是宿主机 cron，不在 compose 里。** 不配它数据就停在导入的那一份（页面会
   如实显示时间，不会假装）。生产镜像里没有 tsx，要跑编译产物。
4. **上线后每个活跃账号都会看到同意屏。** 这是预期行为。Web export 和 API 要一起发。

## 仍然开着的

- 「暂不同意」不改变任何事，待法务确认。
- **基线档案里存下来的那一份基因值，清不掉。** 患者保存一次「编辑资料」，表单会把它
  当时读到的单倍型和甲基化原样回传、写进档案，而报告只补空着的那一格，后台又不许改
  （连清空都拒）。导出读的是档案，那一格会一直是旧值。这一版没有给它留出口。
- **报告读数的修正入口只画在报告详情页上。** 护照这一家不知道报告的状态，所以它们不说
  「打开那份报告怎么改」，只留下指向「编辑资料」的那一句——而单倍型和甲基化在那张表单
  上没有框，想改的患者要自己走到那份报告上。这是这一版故意收窄的，不是遗漏——但它确实
  多了一步。
- **这一版没有在真机微信浏览器里跑过。** 测试驱动的是控制器吐出的响应形态；前端以
  web export 形式在微信 X5 内核里打开，这一层没有覆盖到。
